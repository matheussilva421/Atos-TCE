## Limite de fonte de código

O texto de AGENTS fornecido diz que `work/tce-extractor` é a fonte. Porém, o
README do checkout, o builder do ZIP v1, os comandos de teste especificados e os
símbolos dos quatro bugs identificam `app/`, `extension/` e `tests/` da raiz
como runtime portátil suportado; `work/tce-extractor` é a árvore legada. A
implementação será feita somente no runtime distribuído da raiz e a árvore
legada ficará intacta. Esta divergência deve ser reconciliada na documentação
do projeto em trabalho futuro, fora do escopo v1.0.1.

## Investigação inicial — causas confirmadas no código

- #2: o scan cria/atualiza `processes` exclusivamente pela chave textual
  `(process_key, interested_normalized)`. O DOM atual já transporta
  `portal_act_id`, mas a persistência não o usa para resolver o `process_id`.
- #3: `FillService.request_fill`, `request_manual_fill` e a UI só aceitam
  `PRONTO`; depois de um preenchimento terminal a lista não é atualizada junto
  com o detalhe.
- #4: o backend persiste o resultado de `OPEN_NEXT_ACT`, mas o sidepanel ignora
  esse resultado e faz uma nova busca `READ_CURRENT_FORM` pela identidade alvo,
  terminando no estado genérico “aceita, mas não confirmado”.
- #5: `openAct()` envia comandos a todas as frames e conserva a última recusa;
  `SCREEN_NOT_NAVIGABLE` pode substituir códigos específicos. O fluxo atual
  também não verifica primeiro se o formulário exato já está aberto.
- Identificadores pessoais reais não foram lidos. Os testes/fixtures existentes
  são sintéticos; nenhuma base de produção foi alterada.
